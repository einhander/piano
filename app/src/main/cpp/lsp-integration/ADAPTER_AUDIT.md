# LADSPA adapter audit (Oct 2026)

Delivery check: the debug APK built in this checkout contains no `lib/*/*lsp*` entries (`unzip -l app/build/outputs/apk/debug/app-debug.apk 'lib/*/*lsp*'`). Build success alone therefore does not establish plugin availability. Supply the documented Android prebuilt and repeat packaging and real-DSP checks before using this APK to validate effects on-device.

`LadspaEffect::prepare` initializes descriptor-declared input controls from LADSPA 1.1 hints; table-backed values are then deliberately overlaid, preserving existing saved parameter values applied through `setParameter`. `DEFAULT_NONE` has no suggested value: initialize at zero, then clamp against any bounded range. Sample-rate hints scale bounds (including default fractions); logarithmic defaults interpolate in log space; integers round and toggles normalize to 0/1. Focused reproducible test: from repo root run `app/src/main/cpp/lsp-integration/tests/run_ladspa_defaults_test.sh` (requires host C++17 compiler only; no external dependencies).

Limiter release: the pinned submodule is `lsp-plugins-limiter` 1.0.36 (pin recorded in `patches/ANDROID_PATCHES.md:49`). Its authoritative metadata header declares `RELEASE_TIME_DFL` as 5: https://raw.githubusercontent.com/lsp-plugins/lsp-plugins-limiter/1.0.36/include/private/meta/limiter.h. Both native tables use 5 ms. This is the upstream default, not a range midpoint. The plugin binary remains unavailable locally, so DSP A/B remains unverified.

Lifecycle/path review: `EffectChain::loadBundle` prepares effects; `LadspaEffect::process` returns unchanged for unavailable or bypassed effects and applies pending values immediately before plugin `run`. Sample rate is passed to instantiate on each prepare. `setParameter` is an atomic store and intentionally does not clamp, avoiding destructive rewriting of persisted configs. No evidence from the bounded adapter path review of a routing/enable-state defect beyond table metadata; host DSP A/B remains unverified because no host bundle is present.

EQ band activation: type default is 0 (Off); select a non-Off band type before expecting frequency/gain changes to affect audio. No UI was changed here. Manual device checks remain required for plugin availability/package loading, audible EQ band activation, compressor response, limiter ceiling, and restoration of existing saved settings.
